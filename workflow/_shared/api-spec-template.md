# API 接口规格模板

> 一份**可复用的接口文档骨架模板**，供新需求编写接口规格时复制填写。
> 全文使用通用占位符，**不含任何业务字段**。复制后把占位符替换成本次需求真实字段即可。

---

## 0. 使用说明

### 0.1 模板用途

为新模块/新需求编写前后端联调用接口规格文档。对齐参考文档的**粒度与详尽程度**：每个接口必须四段齐全——

1. **项目说明表**（接口名称 / 请求方式 / URL / 用途 / 所属模块或 Tab / 类型）
2. **请求参数表**（参数 / 类型 / 必填 / 示例 / 说明）
3. **响应示例 JSON**（完整、多字段、含嵌套对象和数组、数值真实可读）
4. **字段说明表**（把响应里每个字段都列出来，数组展开到 `xxx[].子字段`，嵌套对象展开到 `parent.child`）

### 0.2 占位符约定

本模板统一使用 **`{{...}}`** 表示需替换的业务占位。复制使用时，**所有 `{{...}}` 必须替换**为本次需求真实值。

| 占位符样式 | 含义 | 示例 |
|---|---|---|
| `{{字段名}}` | 字段名占位，替换为真实业务字段 | `{{fieldA}}` → `orderNo` |
| `{{字段Key}}` | 对象/array 的字段 key 占位 | `{{listKey}}` → `records` |
| `<...>` | HTML 注释中的填写提示，非占位 | `<!-- 说明：... -->` |

### 0.3 四段式必填要求（硬约束）

- **禁止**只写描述，必须用「项目说明表 + 请求参数表 + 响应示例 + 字段说明表」四段式。
- 响应示例 JSON 中的字段必须与字段说明表**一一对应**，不得遗漏、不得多写。
- 数组字段**必须展开**到子字段（见 §6.2 强制规则）。

## 1. 统一响应结构规范

> ⚠️ 本节给的是一个**示例**，实际结构以各项目后端约定为准（Java 项目常用 `Protocol<T>` 的 `returncode / message / data`，前端联调项目常用 `returncode / message / result`）。请按当前项目实际结构替换，全文统一即可。

示例信封：

```json
{
  "returncode": 0,
  "message": "success",
  "result": { ... }
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `returncode` | `number` | 返回码。`0` 表示成功；非 `0` 表示业务异常，具体码值见各接口异常说明 |
| `message` | `string` | 提示信息。成功固定为 `"success"`；失败为可读的错误描述 |
| `result` | `object` / `array` / `null` | 业务数据载体。成功时为具体业务对象；失败时为 `null` |

## 3. 分页表格接口范式（核心，必须有）

> 适用场景：返回**多行结构化记录**的接口（表格类）。
> 参考文档中此类接口为全量返回，**本模板强制要求支持分页**。

### 3.1 分页请求参数（追加到接口的请求参数表）

表格类接口除业务过滤参数外，**必须**追加以下分页入参：

| 参数 | 类型 | 必填 | 示例 | 说明 |
|---|---|---|---|---|
| `pageNo` | `number` | 否 | `1` | 页码，默认 `1`，从 1 开始 |
| `pageSize` | `number` | 否 | `10` | 每页条数，默认 `10`，最大 `100` |

### 3.2 分页响应结构

`result` 下必须包含分页包装字段 + 列表数据数组。

> ⚠️ **数组字段名由各接口文档自行定义，无统一约定**。常见命名 `list` / `records` / `rows` / `data` / `items` 等，同一份文档内保持统一即可。模板中用 `{{listKey}}` 占位。

| 字段 | 类型 | 说明 |
|---|---|---|
| `pageNo` | `number` | 当前页码 |
| `pageSize` | `number` | 每页条数 |
| `total` | `number` | 符合条件的总记录数 |
| `pages` | `number` | 总页数（= `ceil(total / pageSize)`） |
| `{{listKey}}` | `array` | 当前页数据数组 |
| `{{listKey}}[].{{fieldA}}` | `{{type}}` | {{元素子字段含义}} |
| `{{listKey}}[].{{fieldB}}` | `{{type}}` | {{元素子字段含义}} |
| `{{listKey}}[].{{fieldC}}` | `{{type}}` | {{元素子字段含义}} |

## 4. 数组字段展开规则（强制，醒目标注）

### 4.1 核心规则

**凡 `type = array` 且元素为对象的字段，禁止**只写一行「字段名 | array | 说明」就完事。**必须**用 `数组字段名[].子字段` 的写法，逐行列出数组元素内部的**每个**字段及其类型和说明。

适用范围：**请求参数表**和**响应字段说明表**里**所有**数组字段，无一例外。

### 4.2 正反例对照

**❌ 错误写法（反例，禁止）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | `array` | 列表数据 |

**✅ 正确写法（展开数组元素的每个子字段）**：

| 字段 | 类型 | 说明 |
|---|---|---|
| `items` | `array` | 当前页数据数组 |
| `items[].id` | `number` | 元素 ID |
| `items[].name` | `string` | 元素名称 |
| `items[].value` | `number` | 元素值，单位：% |

### 4.3 嵌套对象继续展开

若数组元素内还嵌套对象，继续往下展开到 `数组字段[].子对象.子字段`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `list` | `array` | 数据数组 |
| `list[].id` | `number` | 元素 ID |
| `list[].info` | `object` | 元素附加信息 |
| `list[].info.label` | `string` | 信息标签 |
| `list[].info.weight` | `number` | 信息权重，单位：% |

### 4.4 基础类型数组不展开

元素为**基础类型**的数组（如 `number[]` / `string[]`）写一行即可，无需展开，但要标注与谁一一对应：

| 字段 | 类型 | 说明 |
|---|---|---|
| `xAxis` | `string[]` | 横轴标签数组 |
| `series[].data` | `number[]` | 数值序列，顺序与 `xAxis` 一一对应 |

### 4.5 数组字段命名声明

列表数组的字段名**由各接口文档自行定义**（可能是 `list` / `records` / `rows` / `data` / `items` 等），模板中出现的 `list` 仅作示例占位，**不是**通用固定命名。同一份文档内命名需统一。

## 5. 字段类型与说明规范

### 5.1 字段类型标注约定

字段说明表「类型」列统一使用以下小写 token：

| 标注 | 含义 | 示例 |
|---|---|---|
| `string` | 字符串 | `"{{示例值}}"` |
| `number` | 数值（含整数与小数） | `123`、`45.6` |
| `boolean` | 布尔 | `true` |
| `object` | 对象（嵌套结构需展开下一层字段） | `{ ... }` |
| `array` | 数组（元素为对象时展开 `[]` 内字段；元素为基础类型时写 `string[]` / `number[]`） | `[1, 2, 3]` |
| `枚举` | 取值可穷举的字段，**必须在说明中列出全部取值** | 见 §6.4 |
| `number[]` | 基础类型数组：数值 | `[1.1, 2.2]` |
| `string[]` | 基础类型数组：字符串 | `["{{a}}", "{{b}}"]` |

### 5.2 嵌套字段写法（强制规则见 §4）

- 对象字段：先写父字段一行（类型 `object`），再用 `父字段.子字段` 逐行列出每个子字段。
- 数组元素为对象：用 `数组字段[].子字段` 逐行展开每个子字段（**禁止**只写一行 array 概括，详见 §4）。
- 数组元素为基础类型：直接写 `string[]` / `number[]`，无需展开，但要标注与谁一一对应。
- 多层嵌套继续往下点，如 `list[].info.weight`。

### 5.3 必填/可选标注

请求参数表「必填」列统一使用：

- `是` — 必填，缺则报错
- `否` — 可选，带默认值时在「说明」列写明默认值

### 5.4 单位标注

带单位的字段必须在说明里写明单位，格式「...，单位：xxx」：

| 字段类型 | 单位示例 |
|---|---|
| 占比 / 比率 | `%` |
| 金额 | `元` / `万元` |
| 计数 | `个` / `辆` / `人` / `次` |
| 时长 | `秒` / `分钟` / `天` |

> 模板中一律用 `{{单位占位}}` 表示，填写时替换为真实单位。

### 5.5 枚举字段规范

**凡可枚举的字段，字段说明必须列出全部取值及含义**。示例（通用占位，不抄任何业务取值）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `{{enumFieldA}}` | `枚举` | {{字段含义}}。取值：`{{OPTION_A}}`={{含义A}}、`{{OPTION_B}}`={{含义B}}、`{{OPTION_C}}`={{含义C}} |
| `{{signedFieldA}}` | `number` | {{带符号字段含义}}。`正数`={{上升含义}}，`负数`={{下降含义}}，`0`={{无变化含义}} |

## 7. 自检清单

填写接口文档时逐条勾选：

- [ ] 所有 `{{...}}` 占位符已替换为本次需求真实业务值。
- [ ] 每个接口都包含「项目说明表 + 请求参数表 + 响应示例 + 字段说明表」四段齐全。
- [ ] 响应示例 JSON 里的每个字段，都在字段说明表中有对应行，一一对应、无遗漏、无多余。
- [ ] **所有数组字段已展开到子字段**（用 `数组字段[].子字段` 逐行列出），没有「字段名 | array | 说明」这种概括写法。
- [ ] 基础类型数组（`number[]` / `string[]`）已标注与谁一一对应。
- [ ] 分页接口的请求参数表含 `pageNo` / `pageSize`；响应 `result` 含 `pageNo` / `pageSize` / `total` / `pages` + 列表数组。
- [ ] 列表数组字段名在本文档内统一（如统一用 `list` 或 `records`），且字段说明里声明了命名。
- [ ] 所有可枚举字段在字段说明中列出了**全部**取值及含义。
- [ ] 所有带单位的字段在说明里标注了单位（% / 元 / 个 / 辆 / 人 / 次 等）。
- [ ] 响应信封全文统一（同一项目只用一种信封结构）。
- [ ] 字段名命名风格全文统一（如统一 camelCase 或 snake_case）。
