## 阻塞级问题

1. **test-cases.md:TC119①/TC120①/TC132/页面级隐私矩阵 — 隐私矩阵列表/Feed/页面级预期与基线数据 P1/P2 设定矛盾（四处同源）**
   - 失败场景：给定基线 A（P1=type=3 标签[12]+指定好友[2李四]；P2=type=4 标签[12]+指定排除[4赵六]），按 design §5.2 走查——
     - 李四对 P1 userHit=true → **可见**；但 TC119① 预期李四列表=[P0,P2,P5] 且注释"P1 未命中"、TC132 预期李四 Feed"不含 P1…（canView 过滤）"、页面级矩阵"李四视角：见 P0/P2/P5，不见 P1"——同一 viewer 同一帖，详情路径 TC100② 断言 code=0，列表/Feed/页面路径断言不可见，**用例集内部自相矛盾且与 design §5.2 规则①冲突**。李四正确投影=[P0,P1,P2,P5]。
     - 赵六对 P2 userHit=true 且 type=4 → **不可见**；但 TC120① 预期赵六=[P0,P2,P5]（含 P2，标注"P2 指定排除"却仍出现在列表）、页面级"赵六视角：见 P0/P2/P5"——与 TC103②（详情 1011）矛盾。赵六正确投影=[P0,P5]。
     - 后果：阶段六 tester 按 TC119/TC120/TC132 写断言，正确实现（canView 单实现，design §5.6 规则 1）必红灯；或 tester 误判"用例语义缺口"触发错误回炉。
   - 攻击维度：清单 5（用例与方案脱钩：design §5.2 声明的行为与用例预期不一致）+ 清单 3（预期不可核对：同一数据示例三路径断言口径分裂）
   - 建议：以 design §5.2 逐步走查为唯一口径重算 5 视角 × 三路径投影，修正 TC119①（李四=[P0,P1,P2,P5]）、TC120①（赵六=[P0,P5]）、TC132（李四 Feed 含 P1）、页面级矩阵李四/赵六两行；顺带复核 TC120② 钱七=[P0,P2,P5]（该行正确）保持不动。

2. **test-cases.md:TC127 — 双锚点用例数据量不足，核心断言组合在给定数据下不可能出现**
   - 失败场景：前置仅"王五连发 60 帖 type=3 空集"，pageSize=20 → batchSize=pageSize×3=60。按 design §5.4 算法推演：第一批 LIMIT 60 恰好取满 60 条不可见帖（batch.size()=batchSize，不置 scanEnd，rounds=1）；第二批取剩余基线 6 帖——张三是作者全部可见，collected=6，batch.size()=6<60 → scanEnd=true break → 输出 **items=基线 6 帖、hasMore=false、nextCursor=null**。用例断言的 `items=[] && hasMore=true && nextCursor≠null`（B1 合法组合）**全部落空**，双锚点防御（design §5.4/§14 B1 修复、tasks T080 验收"B1 场景可复现"）无任何有效用例守护。tasks T080 验收标准自身要求"构造连续 ≥9×pageSize 条不可见候选"（=180），60 帖只有 3×pageSize，量级差 3 倍。
   - 攻击维度：清单 5（用例与方案脱钩：与 tasks T080 验收标准冲突）+ 清单 3（预期不可核对：数据设定与预期经算法推演不相容）
   - 建议：前置改为构造 **≥181 条**对张三连续不可见且新于基线的候选（如王五/多好友合计连发 200 帖 type=3 空集），使 3 轮×60 条扫描窗口全部不可见且第 3 批满批（scanEnd=false），方可触发 items=[]&hasMore=true&nextCursor≠null；续翻②的"跳过 N 帖后基线帖可见"同步按新数量调整。

3. **test-cases.md:TC058 — 预期错误码与 tasks.md T030 校验顺序矛盾（design 与 tasks 顺序相反，用例预期悬空）**
   - 失败场景：`POST /api/friend-tags/11/users/999999`（999999 不存在且必非张三好友）。tasks T030 bindUser 伪代码校验顺序为"归属(1004/1006) → existsFriendship=0(1007) → userMapper 存在性(1002) → 查重(1008)"——好友关系校验先于用户存在性，该请求应返回 **1007**；TC058 断言 1002（跟随 design §3.2.9 异常码罗列顺序，1002 列在 1007 之前）。design 与 tasks 对校验顺序的表述相反，方案未定稿，用例 whichever 都可能红灯；且若 1007 先行，绑定入口的 1002 分支实际不可达（不存在用户必非好友），TC058 成为永红用例。
   - 攻击维度：清单 5（用例与方案脱钩：预期与 tasks 实现基准冲突）
   - 建议：先由主 agent 裁决 bindUser 校验顺序（见待澄清 2）定稿 design/api/tasks 三处一致；用例按裁决结果改写 TC058 入参或预期（若 1007 先行，1002 分支用例应改为注记"顺序裁决后不可达"或以 SQL 造"存在但非好友边界"数据覆盖 1007 主路径）。

4. **test-cases.md:入口14/入口3 — 幂等三件套与 MECE 自查声明与事实不符（两处）**
   - 失败场景一：文档统计行与覆盖核对均声称"9 个写入口（6/7/8/9/10/11/12/14/17）均有重复/并发/重试用例"，逐一核对：入口14（删帖）仅有 TC116（重复）/TC117（并发），**缺"失败重试"用例**——对照入口10 TC072 的对称结构（①1006 越权失败 → ②修正 viewer 重试成功），删帖缺"1012 越权被拒 → 修正为作者重试成功"闭环；若实现将归属校验写反（误删他人帖）而 TC112 恰好漏跑，无第二道防线。
   - 失败场景二：入口3 tagId 参数维度声明"有效：>0 且归属当前用户（**过滤命中/无命中**）"，但 TC015-TC018 无"合法标签+零绑定好友 → data=[]"用例（基线 A 三标签均有绑定，场景缺位）——声明的 MECE 分支无落地用例，阶段六 tester 按维度表生成映射时该分支悬空。
   - 攻击维度：清单 1（覆盖缺口：分支漏测）+ 清单 2（幂等三件套缺失）+ 清单 6（自查声明与事实不符误导阶段五冻结）
   - 建议：入口14 补 1 条失败重试用例（对称 TC072 结构）；入口3 补 1 条"新建空标签（无绑定）按 tagId 过滤 → data=[]"用例；或如实修订统计行/维度声明并说明豁免理由（不建议，两场景成本极低）。

## 建议级问题

1. **TC126 nextCursor 断言值格式沿用 explore 种子的时间字面量**：`nextCursor=Base64("10:00:00.000:102")` 不匹配 api.md 接口16 定稿正则 `^\d{13}:\d{1,18}$`（毫秒:postId，示例 `MTc4OTkxODIwMzAwMDoxMDI=`）；explore Q1 规则⑤的示例格式是阶段二早期产物，design/api 已定稿毫秒格式，TC129③④ 也用了正确毫秒格式。tester 按该字面值做相等断言必失败。应对齐为 Base64("{毫秒}:102")。
2. **并发用例预期过于确定，未留竞态窗口**：TC053（并发删标签："1 笔 code=0 + 1 笔 1004"）与 TC117（并发删帖："作者 1 笔 0 + 1 笔 1010；李四 1012"）——先查后改窗口下两笔作者请求可能都通过校验、串行 UPDATE（第二笔 0 行命中仍返回 code=0），预期组合写死会间歇性红灯。对照 TC033/TC063 已采用"理想 X / 极端窗口 Y 留痕"写法，应统一为：终态断言为主（DB is_del=1、无数据损坏）+ 响应码组合列出可接受路径。
3. **有效上界单侧边界缺失**：tagName 恰 16 字、content 恰 2000 字（均为有效上界）无用例，仅有 17 字/2001 字越界侧；TC087④"content 与 imageUrls 同空"未含 content=纯空格+无图的 trim 组合（trim 后为空应同判 1001）。
4. **观测型用例判定口径未定义**：TC075 分布容差 ±5pp 未定义分母（主标签绑定数 1000 vs 含 30% 次标签的总绑定数 1300——同事口径 25% vs ≈19.2%，差值大于容差本身）；TC079 type 分布（仅 50 样本）未给容差数值且未标"观测软校验不计红灯"标签（TC075/TC135 均已标）。
5. **冗余未压缩**：TC049 与 TC052（已删标签再删 → 1004）、TC114 与 TC116（已删帖再删 → 1010）为同路径重复（"连发"=第一次成功+第二次已删态，与"已删态再删"完全同分支），可各合并省 2 条。
6. **TC015 未断言过滤视图下 tagNames 内容**：api.md 接口3 tagNames 语义为"该好友的全量标签名列表"（非仅过滤标签），过滤分支走 selectFriendIdsByTag 数据源后 tagNames 组装是否仍全量（王五=[同事,朋友] 而非 [同事]）无用例守护，实现易在过滤分支丢失 tagNames 或缩水。
7. **前置自含性两处**：TC031 前置"删除张三'球友'标签"——基线 A 无球友标签，需声明准备手段（SQL 直插 is_del=1 或依赖 TC028 后删除）；TC109 前置"张三删 P3 后"同理（无对应删除用例删 P3，TC110 删的是 P0），需声明 SQL 准备或调整引用。
8. **TC082"模拟中断（生成中停服务）"可执行性存疑**：JUnit 集成测试无法优雅"停服务"，需明确手段（独立进程启动+kill、超时中断、或降级为手工验证项留痕），否则该断言（重跑后库内干净数据）无法自动化。
9. **TC135"无跳空异常"判定标准未定义**：mock 数据全集不可确知，"跳空"无法判定；建议改为可判定口径（全程 postId 无重复 + 恰好终止于 hasMore=false + 拉取总数=DB 可见候选数抽样核对）。
